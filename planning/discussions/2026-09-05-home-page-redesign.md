# Home page redesign

Vincent (2026-09-05): *"The home page https://wiki.bigledger.com/ is quite ugly too, need redesign."*

## Diagnosis (2026-09-05, from the live page)

**1. It is a rendering bug before it is a design problem.** `layout: hextra-home` wraps the
content in `hx:flex hx:flex-col hx:items-start`; anything without an explicit width shrinks
to fit. Measured on the live page: the `{{< cards >}}` grid is **483 px wide with one
column** (`grid-template-columns: 483px`), every H2 is **16 px** (no prose styling in that
layout), and 28 cards therefore stack into a **4-screen-tall left-hand strip** with two
thirds of the viewport empty. Hextra's own home page avoids this with
`hextra/feature-grid` / `feature-card` and `hx:w-full` wrappers — components this page never
uses. Mobile is 5.2 screens, opening with a wall-of-text callout before any navigation.

**2. It is a marketing landing page, not a docs home.** "Start Free Trial", "Pricing Plans",
"Contact Sales", "Trusted by 1 Million Users", "99.9% Uptime SLA", "What Makes BigLedger
Different". A reader who arrives here already has BigLedger; they want to *do* something.
Those items belong on bigledger.com (where they already are).

**3. Duplication and dead ends.** Manufacturing appears twice; "Quick Start" three times in
three places; six industry cards all lead to the same section; the hero subtitle repeats the
badge; `/developers/postman/` is a 404; module cards point at the old `modules/` tree while
the nav points at `modules-v2/`.

## Proposal — phase 1 now, phase 2 after the restructure

A docs home has one job: get the reader to the right section in one click. Xero Central,
Stripe Docs and Atlassian all reduce to: **short hero → search → 6–8 intent cards → a thin
"by role" / "reference" / "popular" layer.** Nothing else.

Draft built at `content/en/home-draft/` (temporary; delete after decision) using only
Hextra's native components:

1. **Hero** — badge (PEPPOL / e-Invoice, factual), headline "BigLedger documentation", one
   subtitle carrying the positioning (cloud-native business OS; API/MCP/SDK), two buttons:
   *Get started*, *Browse applets*. No marketing numbers.
2. **Search box** on the page (the existing `search` shortcode).
3. **"What do you want to do?"** — 8 `feature-card`s by intent: Get started · Set up your
   company · Sell and get paid · Buy and pay suppliers · Close the books · Submit e-Invoices ·
   Manage stock · Run the point of sale. Phase 1 points them at today's best pages; phase 2
   re-points them at the ADR-0001 tree (`setup/`, `processes/order-to-cash/`, …) — a
   ten-line edit.
4. **Guides by role** — 8 compact cards (`cols=4`) → `guides/roles/*`.
5. **Reference** — Modules · Applets · Developers (API, SDK, MCP).
6. **Popular right now** — 5 links (to be driven by analytics later; hand-picked now).
7. One line: Support · Video training · Product site.

Measured on the draft: desktop 2.3 screens (was 4.0), first grid 1,392 px wide (was 483),
H2 still 16 px — hextra-home applies no heading styles; fixed in a follow-up with Hextra-shipped text classes, 19 cards (was 28), mobile 4.6 screens (was 5.2).

**Welcoming visual (Vincent asked, 2026-09-05):** added a **platform map** — an inline SVG
in the hero's right column: ten modules around the ledger core, applet dots inside each,
and an API · MCP · SDK bar to "AI agents and your own systems". Generated by
`layouts/shortcodes/platform-map.html` (positions computed, no hand paths), `currentColor`
so it works in dark mode. Hero layout is `layouts/shortcodes/hero-split.html`, using only
the grid classes Hextra ships (`hextra-feature-grid hx:grid hx:sm:max-lg:grid-cols-2 …`) —
invented responsive variants like `hx:md:flex-row` are NOT in Hextra's compiled CSS and
silently do nothing.

Files (uncommitted until decided): `content/en/home-draft/_index.md`,
`layouts/shortcodes/hero-split.html`, `layouts/shortcodes/platform-map.html`,
`layouts/_partials/shortcodes/platform-map-inline.html`.

**Removed:** Start Free Trial, Watch Demo, Pricing, Contact Sales, Partner cards, the
statistics block, "What makes BigLedger different", the industry grid (industries get their
hub page under `user-guide/industries/` in ADR-0001), the tabs.

## Not started — questions to settle before any design work

1. **What is the home page for?** A docs home usually has one job: get the reader to the
   right section in one click. Candidates for the primary paths, per ADR-0001: Getting
   started · Set up · How-to · Business processes · Modules · Applets · Developers · Support.
2. **Sequencing.** The home page must link into the *new* tree. Redesign lands with or after
   the restructure, not before — otherwise it is built twice.
3. **Constraints.** Hextra: no inline-styled divs, no CSS grid in markdown (CLAUDE.md).
   Hextra's own hero components (`hextra/hero-*`, `cards`) are the toolkit; anything beyond
   that is a `layouts/` override, which is allowed but must stay theme-upgrade-safe.
4. **Reference points.** Xero Central, QuickBooks support home, Stripe docs home — each is a
   search box + 6–8 large entry cards + a thin "popular" strip. Nothing else.
5. **What is wrong with the current one, specifically?** To be captured from Vincent —
   density? visual style? wrong entry points? all three? (See inbox F-0006.)
