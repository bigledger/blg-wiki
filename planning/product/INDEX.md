| P-0031 | **An unknown 25-character bearer token triggers a full-table Argon2 scan of every credential in the master database.** `AccessKeyDatabaseValidator.getFromDb` runs `SELECT * FROM app_login_principal WHERE credential is not null AND credential != '' AND status != 'DELETED'` (`AppLoginPrincipalUow.java:477-480`, ~8,900 rows today) and Argon2-verifies the candidate against each. **Measured against production 2026-09-06: one unauthenticated request returned 403 after 82.8 seconds**, against sub-second for every other rejection. Unauthenticated, trivially repeatable, and it burns a request thread and CPU per attempt. | P-0032 | **The bare-bearer access-key path skips the expiry check.** A 25-character `Authorization: Bearer` value is validated by `AccessKeyDatabaseValidator` (`AccessKeyDatabaseValidator.java:42-46`), which matches the Argon2 hash and returns the subject — it never reads `valid_date_end`. Fix: apply the same expiry check, or remove the path. | auth | F-0298 |
| P-0038 | **`orderBy` is concatenated into SQL with no allowlist.** `String.format("hdr.%s", criteria.getOrderBy())` is interpolated straight into the query text (e.g. `GenericDocumentUow.java:370-377, 392-399, 406-411`; the same shape in `BaseUowV2.java:14-15, 49, 83` and ~dozens of UOWs), while every other criterion is a bound parameter. Any authenticated caller — including an integration key scoped to one read-only resource — controls that fragment. Code-evidenced only; deliberately not tested against production. Fix: validate `orderBy` against the entity's column list before it reaches the query. | data access | F-0298 |
| P-0045 | **A member can self-approve and self-issue a warranty certificate.** `product-registration/login-entity-ep` and `warranty-certificates/login-entity-ep` check only `isUserLoginEntity(caller, entity_hdr_guid)`, and `approval_status` is never validated (it appears only as a query filter), so a logged-in customer can post a registration already marked `APPROVED` and then post a certificate for it, bypassing back-office review entirely. Delete on `login-entity-ep` is likewise scoped only to ownership. | warranty | F-0304 |
| P-0062 | **An expired-but-real platform JWT with `sysAdminRank: ADMIN` was published on wiki.bigledger.com for nine months.** RS256-signed, `subjectGuid a982e148-…`, `sysAdminGuid 1dd4556c-…`, `exp 2025-12-14T08:34:34Z`; live from commit `97a325cc` (2025-11-26) in `modules/membership/api-reference/GET Membership Points Current Balance.md` and `POST Create Member Point Transaction.md`, duplicated into `modules-v2/` by `feb58e52` (2026-06-19).
