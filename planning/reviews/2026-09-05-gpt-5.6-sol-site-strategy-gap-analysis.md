# GPT-5.6-sol: what the wiki still needs to be best-in-class

# Bottom line

Treating ADR-0001/0002/0003 as implemented, the wiki will have a cleaner shelf, accurate applet identity, and a sane translation priority. It will still not be best-in-class because its content lifecycle, trust signals, task coverage, search, support layer, release discipline, and technical SEO are immature.

The strongest evidence is operational:

- 28 English files publish explicit WIP, TODO, or “under review” notices.
- [Cashbook Applet](/home/marketing/repos/blg-wiki/content/en/applets/master-data/cashbook-applet.md:37) contains unresolved Git conflict markers and mojibake.
- [Cost and ROI Questions](/home/marketing/repos/blg-wiki/content/en/support/beginner-guide/cost-and-roi-questions.md:541) publishes an AI tool-call artefact.
- [The home page](/home/marketing/repos/blg-wiki/content/en/_index.md:20) and [footer](/home/marketing/repos/blg-wiki/layouts/partials/custom/footer.html:8) contain at least 10 customer-visible 404 links.
- `enableGitInfo: true` is set, but the custom single-page layouts omit Hextra’s last-updated, pager, proper breadcrumb, and page-context components.
- No rendered page-level `hreflang` or JSON-LD was found.
- English search data is 7.5 MB; `static/images/` is 863 MB, including 64 MB GIFs.
- CloudFront served tested HTML without gzip/Brotli; pages were 361–579 KB uncompressed.
- [deploy.yml](/home/marketing/repos/blg-wiki/.github/workflows/deploy.yml:29) runs only Hugo, not the existing lychee or Playwright suite.

The benchmark gap is substantive. Stripe couples versioned APIs with a changelog and direct Markdown/“copy for LLM” access; Xero articles use outcome summaries, device variants, “What’s next?”, related answers, feedback, and support escalation; Odoo has a documentation version selector and a defined GitHub review path; Atlassian explicitly separates documentation, knowledge base, community, status, billing, and “What’s new.” [Stripe versioning](https://docs.stripe.com/api/versioning?lang=curl), [Xero article pattern](https://central.xero.com/0/article/Navigate-Xero-using-the-menus-and-icons), [Odoo contribution workflow](https://www.odoo.com/documentation/19.0/nl/contributing/documentation.html), [Atlassian support architecture](https://support.atlassian.com/cloud/).

## 2. Professional / credible

Current trust defects:

- [hugo.yaml](/home/marketing/repos/blg-wiki/hugo.yaml:6) records Git history, but `params.displayUpdatedDate` is absent. More importantly, [layouts/single.html](/home/marketing/repos/blg-wiki/layouts/single.html:1), `layouts/applets/single.html`, and `layouts/modules/single.html` omit Hextra’s `last-updated.html`.
- No English page has `author:` or `reviewer:`. Use stable team ownership, for example `owner: finance-product-team`, plus `last_verified:` and `verified_against:`. Do not expose arbitrary Git commit authors as subject-matter reviewers.
- No “Was this helpful?” mechanism. `params.comments.enable: false` is not the issue; helpfulness needs a small event endpoint and reason choices such as inaccurate, unclear, outdated, or missing steps.
- The four good accounting guides are not uniformly illustrated: only Chart of Accounts contains screenshots.
- There are 1,766 image assets, but no screenshot manifest, capture date, UI build, redaction checklist, or freshness owner.
- WIP content should remain in `planning/drafts/` or be `draft: true`; never publish a WIP banner.
- [The home page](/home/marketing/repos/blg-wiki/content/en/_index.md:148) makes unsubstantiated “1M+ users”, “99.9% SLA”, and “24/7 support” claims. [hugo.yaml](/home/marketing/repos/blg-wiki/hugo.yaml:28) still calls BigLedger a “Next-Generation Blockchain Platform.” Both damage credibility until product/legal verifies them.
- `/privacy/`, `/terms/`, and `/security/` are linked globally but return 404.

For a SaaS product, do not version the entire user manual unless customers genuinely run several supported releases. Show “Last reviewed” and “Applies to” instead. The API needs real versioning and a changelog; Stripe demonstrates why those are inseparable. [Stripe API changelog](https://docs.stripe.com/changelog).

## 3. Organisation and navigation

Hextra is already v0.12.1, the latest tagged release found. The problem is local overrides.

- Hextra’s native docs template includes breadcrumb, page-context menu, last-updated date, previous/next pager and comments. The repo overrides remove nearly all of them; compare [theme single.html](/home/marketing/repos/blg-wiki/themes/hextra/layouts/docs/single.html:7) with [repo single.html](/home/marketing/repos/blg-wiki/layouts/single.html:1).
- Applet/module breadcrumbs are hard-coded, English-only, and collapse the real ancestor chain.
- The theme sidebar stops recursion at four levels in `themes/hextra/layouts/_partials/sidebar.html:71`; current content reaches five. Deep API pages can disappear from navigation.
- `params.sidebar.fold`, `showPages`, `showCategories`, `showTags`, and `forceEnable`, plus most custom `toc` keys in [hugo.yaml](/home/marketing/repos/blg-wiki/hugo.yaml:97), are not consumed by Hextra v0.12.1. They create false confidence.
- Hextra supports image zoom, updated dates, pager, tags, global banner and Markdown page context. None is effectively enabled.
- Tags are uncontrolled: approximately 644 generated tag pages, despite tags being hidden. These pages enter the sitemap and dilute navigation/search. Define a controlled taxonomy or disable taxonomy/term output.
- Related-link headings have more than a dozen variants. Standardise on “Related tasks,” “Applet reference,” “Troubleshooting,” and “Next step.”
- FlexSearch uses full content and forward tokenisation. There is no title boost, product-term synonym map, result filtering, spelling tolerance policy, zero-result telemetry, or task/reference distinction. Search results can rank a stale reference card above the correct guide.
- Per-language indexes already exist, which is good, but Arabic’s 48 KB index cannot answer most user questions.
- The top bar should be: User guide, Modules, Applets, Developers, Support. Search should be the persistent control, not a redundant “Search” menu page.
- Every section landing page should own: intended audience, first three tasks, common problems, full contents, and recent changes. It should not be a 1,000-word marketing catalogue.

The home page should be a prominent search box, eight ADR-0001 entry paths, “Popular tasks,” “New in BigLedger,” and support escalation. The existing partner/pricing/statistics material belongs on `bigledger.com`, not the documentation front door.

## 4. Informative: the reference layer

[APPLET_TEMPLATE.md](/home/marketing/repos/blg-wiki/APPLET_TEMPLATE.md:1) is a 541-line kitchen sink. It mixes installation guides, workflows, business marketing, database schema, hardware requirements, API reference and release history. That encourages authors to invent irrelevant sections.

Observed consistency is poor across 168 regular applet pages:

- Permissions headings: 33.
- Lifecycle headings: 34.
- Related applets: 30.
- Troubleshooting: 27.
- Integration points: 14.
- GL posting: 2.
- Error messages: 1.
- API reference/version history: 0.
- 41 applet pages contain no image.
- Only 5 applet pages link back to a guide; 25 of 83 guide pages link to an applet.

Replace the template with a required core and conditional blocks.

Every applet page:

- `applet_code`, exact store name, plain-English purpose, scope/non-scope, navigation path.
- Product owner, `last_verified`, applicable UI build/release.
- Required applets/configuration and data consumed/produced.
- Screen/tab map with real screenshots.
- Action-level permission matrix: view/create/edit/finalise/void/export/configure.
- Audit behaviour, exports/reports, common errors.
- Related tasks, processes, modules and applets.

Conditional, never fabricated:

- Document lifecycle/state diagram and allowed transitions.
- GL posting table with trigger, debit, credit, tax, reversal and period effect.
- Approval workflow and segregation-of-duties controls.
- API/webhook links to the generated developer reference.
- Data retention, batch limits and external-system behaviour.

Cross-link rule:

- A guide links to the applet reference at the first high-friction screen and again under “Reference.”
- An applet links to the three to five tasks that use it.
- Module pages link to both, but do not duplicate either.

## 5. SEO

Current technical state:

- `<title>` is already `Page – BigLedger Documentation`. Change the suffix to `BigLedger ERP Documentation`; do not stuff `akaun.com` into every title.
- 563 of 620 English files declare `description:`; 565 declare `title:`. Missing metadata is concentrated in UCC/API pages.
- Canonicals render correctly.
- Translated alternates appear in Hugo sitemaps, but no page-level `hreflang` or `x-default` renders.
- The sitemap works, but includes hundreds of low-value tag URLs.
- `robots.txt` is only `User-agent: *`; there is no sitemap declaration.
- Rendered pages contain no JSON-LD.
- Open Graph has title/description/URL, but no reliable `og:site_name` or default image. Twitter cards are text-only.
- Image syntax usually has non-empty alt text, but there is no semantic-alt lint.
- Eight Markdown files embed base64 images; those should never reach content.
- Current CloudFront responses lack compression. Large HTML, 64 MB GIFs and multi-megabyte PNGs make “Hextra is lightweight” irrelevant.

Implement in `hugo.yaml`, `layouts/_partials/custom/head-end.html`, `layouts/_partials/schema.html`, `layouts/_partials/opengraph.html`, and the content schema:

- Organization + WebSite on the home/About pages.
- BreadcrumbList on all non-home pages.
- Article/TechArticle semantics for manuals and reference articles.
- SoftwareApplication on the canonical BigLedger product/About page and reference it through `about`.
- Avoid investing in `SearchAction`: Google removed the sitelinks search box in 2024. Avoid claiming `HowTo` rich-result benefit: Google has also removed HowTo support. [SearchAction retirement](https://developers.google.com/search/blog/2024/10/sitelinks-search-box), [HowTo removal](https://developers.google.com/search/updates), [Breadcrumb guidance](https://developers.google.com/search/docs/appearance/structured-data/breadcrumb).

Structured data helps search engines understand content and qualify pages for supported rich results; it does not guarantee ranking or display. [Google structured-data guidance](https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data).

## 6. GEO

Evidence-based:

- Crawlable, indexable, unique, well-linked, current content is the foundation. Google explicitly says its AI features use core Search ranking and quality systems. [Google’s current AI-search guidance](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide).
- Allow `OAI-SearchBot` for ChatGPT search and citations. `GPTBot` is the separate training control. [OpenAI publisher guidance](https://help.openai.com/en/articles/12627856-publishers-and-developers-faq).
- For Claude search, the relevant agents are `Claude-SearchBot` and `Claude-User`; `ClaudeBot` is primarily training. [Anthropic crawler definitions](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler).
- Allow `PerplexityBot` and ensure CloudFront/WAF does not block its published IPs. [Perplexity crawler guidance](https://docs.perplexity.ai/docs/resources/perplexity-crawlers).
- Keep Googlebot and Bingbot indexable. `Google-Extended` controls model use, not ordinary Google Search visibility; it is not an “AI Overview ranking” switch.
- Stable URLs, canonicals, accurate publisher identity, accessible semantic HTML, descriptive links and an authoritative About page make attribution easier.

Current `User-agent: *` already permits these crawlers. Explicit allow blocks merely document policy; they do not create a ranking gain. WAF and access-log verification matter more.

`llms.txt`:

- The site does generate an LLM-oriented file, but [hugo.yaml](/home/marketing/repos/blg-wiki/hugo.yaml:11) sets `baseName: index`, so it publishes as `/index.txt`; `/llms.txt` and `/llms-full.txt` return 404.
- Its summary says “Next-Generation Blockchain Platform,” so even the machine-readable identity is wrong.
- `llms.txt` is an emerging proposal, not a universal indexing standard. The specification calls for a curated index plus page-level Markdown alternatives. [llms.txt proposal](https://llmstxt.org/).
- Google explicitly says it ignores `llms.txt` for rankings and AI features. It may still help coding agents and platforms that voluntarily consume it.
- Prefer `/llms.txt` plus `.md` versions of important pages. A monolithic 620-page `llms-full.txt` is expensive and stale-prone; if provided, split by user-guide/applets/developers and cap output size. Stripe’s direct Markdown representation is the stronger model.

Canonical naming:

- Product: **BigLedger ERP** on first mention; **BigLedger** thereafter.
- Publisher: **BigLedger Sdn Bhd**.
- `akaun.com`/`Akaun` should appear only in a verified alias statement on `/about/`, legacy-search synonyms, and `sameAs` metadata if the legal relationship is confirmed.
- Never alternate casually between “BigLedger,” “Akaun,” and “akaun.com” as though they were three products.

Useful but not proven citation-ranking levers:

- Question-shaped headings, definitional opening paragraphs and short answer summaries improve passage usability. They are sound editorial practice, not a guaranteed GEO algorithm.
- Repeating the brand in every heading, keyword stuffing, synthetic third-party mentions, and schema inflation are folklore or spam.

## 7. Quality system

Cheap PR checks:

- Content-type front-matter schemas: guide vs applet vs module vs API.
- Required `title`, `description`, integer `weight`; unique `applet_code`; valid aliases.
- Duplicate canonical URLs, titles within one section, applet codes and aliases.
- Missing `_index.md`, orphan pages and pages unreachable from any landing page.
- Broken links, fragments and images.
- Empty or meaningless alt text; base64 images.
- Conflict markers, mojibake, raw `<function_calls>`, TODO/WIP banners.
- Guide structure: opening outcome/time, prerequisites, numbered steps, success check, common mistakes, related documentation.
- Reference-card smells in guides: excess tables, uppercase identifiers as headings, repeated “Required/Immutable,” missing examples.
- Translation-path parity and Bahasa Indonesia blocklist from ADR-0003.
- Rendered canonical, `hreflang`, JSON-LD, OG and one-H1 smoke tests.
- OpenAPI validation with Spectral.

Reading-level scoring should warn, not fail. Malaysian accounting terminology and short UI labels distort Flesch scores; the charter-specific smells are better gates.

Infrastructure-dependent:

- Applet-registry parity: scheduled/self-hosted job with read-only DB access, not GitHub-hosted credentials.
- Screenshot freshness: authenticated test tenant, stable fixtures, UI-build manifest and perceptual diffs.
- Permission and GL-posting verification against source code/test transactions.
- Search zero-result analytics, helpfulness data, 404 telemetry and crawler access logs.
- Translation quality review by native speakers.

Most importantly, make PR quality a dependency of deploy. Today [tests/run-all.sh](/home/marketing/repos/blg-wiki/tests/run-all.sh:20) exists, but [deploy.yml](/home/marketing/repos/blg-wiki/.github/workflows/deploy.yml:29) bypasses it.

# Where I disagree

- ADR-0001: ERP-jargon slugs such as `order-to-cash` optimise for implementers, not the accounts clerk named in the charter. Use plain-English canonical slugs and retain ERP terms as aliases/search synonyms. “Roles and industries own nothing” is also too rigid: their hubs must own curated checklists and decision context, even if they duplicate no procedures.
- ADR-0002: “ACTIVE only” and exact registry titles make an operational database the editorial authority. Retired applets need stable deprecation/tombstone pages, and registry typos or technical names should not automatically become public titles. Keep exact `registry_name` separately from an editorial `title`.
- ADR-0003: equal support for three languages without equal reviewer capacity guarantees stale Arabic and a misleading language switcher. Declare service levels honestly: supported language, translation coverage and review freshness are three different things.
- Charter: forcing GadgetSphere into every guide will become repetitive and absurd for HR, manufacturing, developer and industry-specific material. Keep GadgetSphere as the default ERP scenario, but define a small controlled scenario suite for contexts it cannot represent credibly.
