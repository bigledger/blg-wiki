## SYSTEMIC — five corrections

1. Replace METHOD’s universal shared-screen claim (`METHOD.md:5-12`) with route discovery: inspect `app.routing.ts` first and classify settings as shared, applet-local, branch, default-selection, or personal. Chart, Cashbook and Stock Availability all use applet-local settings components.
2. Require four proofs per setting: **declared, rendered, persisted, consumed**. Model-only keys must be excluded; runtime-only keys get a separate subsection. Make `applet-scan.sh` fail on documentation of model-only keys.
3. Extend `sources:` to all factual sections. Require exact existing files—not directories or database prose—and require the document DCO, posting service, permission extract, and issue URL/ID where used.
4. Add a mandatory generated posting proof block: server document type, amount signum, quantity signum, Dr/Cr equation, GL precedence, stock processor and void reversal. Cross-check inverse document pairs automatically.
5. For “default”, “must”, “blocks”, or “hard stop”, require two citations: UI initial/null-patch logic for defaults, and the exact backend validator/throw for hard stops. Explicitly distinguish client confirmation from backend rejection.

## DISAGREEMENT WITH THE STANDARD

- Front-matter-only citations (`standard:63`) are not traceable enough for 400-line pages. Keep the body clean, but add claim/source IDs or per-section source maps.
- Requiring “Who can change it” in every settings row (`:43-45`) creates redundant columns when authority is uniform; allow one authoritative sentence above the table.
- Restricting Lifecycle to document applets (`:52-54`) leaves master-data and read-only effects underspecified. Every page needs a “Lifecycle and effects” section, even if it states that the applet only reads derived data.
- “Not configurable in this applet” (`:66-67`) is too absolute. Require “No exposed control found in commit X” plus the route/search evidence.
