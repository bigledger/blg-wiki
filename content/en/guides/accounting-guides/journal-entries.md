This guide walks finance users through posting **manual journal transactions** in the **Ledger and Journal Applet** — the one place where users (rather than upstream applets like Sales Invoice or Purchase Invoice) write directly to the general ledger. Use it for accruals, depreciation, reclassifications, opening balances, and audit adjustments. For field-by-field reference, see the [Ledger and Journal Applet](/applets/finance/ledger-and-journal-applet/) documentation.

{{< callout type="info" >}}
**There is no separate "post" step**
The moment you click **Save**, BigLedger assigns a posting running number, sets the journal to `POSTED`, and updates the trial balance. To reverse a mistake, use **Void** (which creates a reversal journal) — do not delete.
{{< /callout >}}

## Concepts

| Term | Meaning |
| :--- | :--- |
| **Journal Transaction** | One header (`bl_fi_jrnl_hdr`) + two or more lines (`bl_fi_jrnl_line`). Each line carries a GL Code, a Sub-Ledger, and either a debit or credit amount. |
| **Manual vs Auto journal** | `auto_flag = MANUAL` journals are typed in this applet. `auto_flag = AUTO` journals are generated by upstream applets (Sales Invoice, Purchase Invoice, POS Cash Bill) when the source document is finalised. This guide covers MANUAL journals only. |
| **GL Code** | The account from the Chart of Accounts. Required on every line. |
| **Sub-Ledger** | The granular bucket under a GL Code (e.g. a specific customer under Trade Debtors, a specific bank account under Cash at Bank). Required on every line. Auto-created from the chosen GL Code if missing. |
| **Posting Running Number** | Two immutable numbers stamped at save time: `posting_running_no` (tenant-wide) and `posting_running_no_by_company` (per company). These are the "Journal No" columns on the listing. |

## Prerequisites

Before posting your first manual journal, confirm:

- The Chart of Accounts is built and the GL Codes you intend to debit and credit are `ACTIVE`. See the [Chart of Accounts Setup Guide](/guides/accounting-guides/chart-of-accounts-setup/).
- The company has a **Primary (PRM) ledger** configured under *Companies → Ledgers*. If missing, save fails with `PRIMARY_LEDGER_NOT_EXIST`.
- The company's **Default GL Codes** are mapped (at minimum `RETAINED_EARNING`, `ROUNDING`, and `FOREX_GAIN` / `FOREX_LOSS` if you handle multi-currency).
- A **Fiscal Year** covering your target transaction date exists, and the relevant Fiscal Period has `closing_status = OPEN` (or `LOCK_GL` if you are authorised to post into a soft-closed period).
- Your user role includes `API_TNT_DM_ERP_FI_JOURNAL_OWNER`, `_ADMIN`, or `_WRITE` on the company.
- *(Optional)* **Settings → Default Selection** has Company, Ledger, and Currency pre-set so the new-journal form fills automatically.
- *(For CSV import only)* You have downloaded `MasterData_Upload_Journal.csv` from the **Import Journal** screen and all referenced master codes exist in the system.

The applet is at **Finance → Ledger and Journal Applet**.

## Step 1: Open Journal Transaction and click New

*Sidebar → Ledger and Journal Applet → Journal Transaction → **New***

The listing shows every journal in the system, both `AUTO` and `MANUAL`. Columns include Journal No, Journal No By Company, Document Type, Document No, Status, and Posting Status. Filter by **Auto Flag**, **Posting Status**, or date range to find an existing journal you want to clone or void.

Click **New** to open the empty Create Journal Transaction form. It has two tabs: **Main** and **Lines**.

## Step 2: Fill the Main tab (header)

Enter the journal-level information. Company and Ledger default from *Settings → Default Selection* if configured.

| Field | Required | Notes |
| :--- | :--- | :--- |
| **Company** (`guid_comp`) | Yes | Immutable after save. |
| **Ledger** (`ledger_hdr_guid`) | Yes | Defaults to the company's PRIMARY (PRM) ledger. Save fails with `PRIMARY_LEDGER_NOT_EXIST` if no PRM ledger exists. |
| **Currency** (`ccy_code`) | Yes | Must already exist in the Currency master. |
| **Reference Number** (`reference_num_1`) | Recommended | Your internal identifier, e.g. `JV-2026-01-001`. Required and must be unique per company when importing via CSV. |
| **Date** (`date_txn`) | Yes | The accounting date. The fiscal period covering this date must not be in `LOCK_TXN` or `LOCK_ALL` status. |
| **Description** (`descr`) | Recommended | Free text explaining what the journal is for. |

{{< callout type="tip" >}}
`date_txn` is the **accounting** date you choose. `date_posting` is set automatically to the system clock when you save. Reports grouped by transaction date use `date_txn`; audit reports use `date_posting`. Backdated journals will have `date_txn` in the past but `date_posting` of today.
{{< /callout >}}

## Step 3: Add Lines on the Lines tab

Switch to the **Lines** tab and add at least two lines. Each line carries either a debit or a credit amount — never both. Total debits must equal total credits.

| Field | Required | Notes |
| :--- | :--- | :--- |
| **GL Code** (`glcode_guid`) | Yes | Must be an `ACTIVE` code from the Chart of Accounts. Pick from the dropdown — typos silently create unintended Sub-Ledgers (see Gotchas). |
| **Sub-Ledger** (`sub_ledger_guid`) | Yes | Auto-resolved or auto-created from the GL Code if you don't pick one. |
| **Branch** (`guid_branch`) | Optional | Use if you run branch accounting. |
| **Entity** (`guid_entity_hdr`) | Optional | Customer / supplier / employee link. Use when the line affects a specific account holder. |
| **Cashbook** (`guid_cashbook`) | Conditional | Required only if the GL Code is a cash / bank account managed by the Cashbook applet. |
| **Debit** (`amt_debit`) **or** **Credit** (`amt_credit`) | Yes | Enter one, leave the other blank. |
| **Description** (`descr`) | Recommended | Line-level narration shown on reports. |
| **Cheque No** (`reference_num_1`) | Optional | For bank lines. |
| **Batch No** (`reference_num_2`) | Optional | For grouped postings. |

Typical patterns:

- **Monthly rent accrual** — `Dr Rent Expense / Cr Accrued Liabilities`
- **Reclassify a posting** — `Dr correct account / Cr wrong account`
- **Opening balance** — `Dr asset or expense / Cr Opening Balance Equity`

{{< callout type="warning" >}}
**Watch the running totals at the bottom of the Lines tab.** The API does not enforce header-level balance on save — an unbalanced manual journal will save and immediately corrupt the trial balance. See [Step 9](#step-9-diagnose-problems-in-error-checking) for how to find and fix unbalanced journals.
{{< /callout >}}

## Step 4: (Optional) Tag analytical dimensions

On each line, open the **Categories** sub-tab to tag analytical dimensions. These don't change the accounting — they drive multi-dimensional reporting in the Financial Report applet.

| Dimension | Typical use |
| :--- | :--- |
| **Segment** (`guid_segment`) | Business segment, e.g. Retail vs Wholesale |
| **Dimension** (`guid_dimension`) | Custom classification |
| **Project** (`guid_project`) | Project-based accounting |
| **Profit Center** (`guid_profit_center`) | Organisational unit attribution |

Tag only the dimensions you actually report on. For a transfer, apply the same dimension tags to both the debit and credit lines so the reports net to zero per dimension.

## Step 5: Save the journal

Click **Save**. The system validates:

- `NOT NULL` on Company, Ledger, GL Code, and Sub-Ledger
- Foreign-key existence for company, ledger, currency, GL Code, and Sub-Ledger
- That the fiscal period covering `date_txn` is not in `LOCK_TXN` or `LOCK_ALL`

If validation passes, the system:

1. Stamps `posting_running_no` (tenant-wide) and `posting_running_no_by_company` (per company)
2. Sets `posting_status = POSTED`
3. Sets `date_posting = now()`
4. Sets `auto_flag = MANUAL`

The journal hits the Trial Balance immediately. If anything is wrong, **do not delete** — use Void (Step 8) to preserve the audit trail.

## Step 6: Bulk import via CSV

*Sidebar → Ledger and Journal Applet → Import Journal*

For migration or large batches, use Import Journal instead of typing each entry.

1. Click **Sample Format** to download `MasterData_Upload_Journal.csv`.
2. Populate the file (one row per journal **line**; lines that share the same Company + Reference Number form one journal).
3. Drag-and-drop the file onto the upload area, or click **Upload File**.
4. Monitor the **Process Status** column on the listing.

### Required columns

| Column | Required | Notes |
| :--- | :--- | :--- |
| `COMPANY_CODE` | Yes | Must match `bl_fi_mst_comp.code`. |
| `LEDGER_CODE` | Yes | Must match a ledger under the company. |
| `REFERENCE_NUMBER` | Yes | **Unique per company** across all non-deleted journals. |
| `CURRENCY_CODE` | Yes | Must already exist in the Currency master. |
| `DATE_TXN` | Yes | Must fall in an unlocked fiscal period. |
| `HDR_DESCRIPTION` | Optional | Header narration. |
| `HDR_BRANCH_CODE` | Optional | Header branch. |
| `LINE_GL_CODE` | Yes (per line) | Must match `bl_fi_mst_glcode.gl_code_1`. |
| `LINE_BRANCH_CODE` | Optional | |
| `LINE_CASHBOOK_CODE` | Optional | Required only for bank / cash GL codes. |
| `LINE_ENTITY_CODE` | Optional | Matches `bl_fi_mst_entity_hdr.customer_code`. |
| `LINE_AMOUNT_DEBIT` | One of D/C | Debit amount; leave blank if credit. |
| `LINE_AMOUNT_CREDIT` | One of D/C | Credit amount; leave blank if debit. |
| `LINE_DESCRIPTION` | Recommended | Line narration. |

### Process Status transitions

`UNPROCESSED → PROCESSING → VALIDATING_DATA → DONE` (success) or `FAILED`.

On `FAILED`, open the row to see `error_message` and the per-column `*_error` fields (e.g. `reference_no_error`, `line_gl_code_error`, `debit_credit_not_tally_error`).

{{< callout type="warning" >}}
**The debit / credit tally is enforced across the whole file**, not per journal. `SUM(LINE_AMOUNT_DEBIT)` over every row in the file must equal `SUM(LINE_AMOUNT_CREDIT)`. If they don't match, every row is flagged and the entire import fails. Verify totals in Excel before upload, or split multi-journal batches into separate CSVs.
{{< /callout >}}

## Step 7: Clone a recurring journal

*Open an existing journal → **Clone***

For recurring entries — monthly rent accrual, subscription expense, depreciation reclass — open the source journal in **View** mode and click **Clone**. A new journal is created with:

- Fresh `posting_running_no` and `posting_running_no_by_company`
- New GUIDs on the header and every line
- `clone_source_jrnl_hdr_guid` pointing back to the source for traceability
- Identical GL Codes, Sub-Ledgers, amounts, descriptions, branches, and analytical dimensions

{{< callout type="warning" >}}
**The clone is posted immediately — there is no draft state.** It uses the cloned `date_txn` and `reference_num_1` until you change them. Update the date, reference number, and amounts before the values diverge from last period's, or void the clone if a major edit is needed.
{{< /callout >}}

## Step 8: Void (reverse) a posted journal

*Journal Transaction listing → select journal → **Void*** (the red button)

To reverse a posted entry, click **Void**. The system:

1. Builds a new reversal journal where every line's `amt_debit` and `amt_credit` are swapped
2. Stamps a fresh `posting_running_no` on the reversal
3. Sets the original journal's `posting_status = VOID`
4. Links the two journals in `bl_fi_jrnl_link`

The original journal stays visible in reports for audit. After voiding, post a new MANUAL journal with the correct entries and reference the voided journal's number in your description.

## Step 9: Diagnose problems in Error Checking

*Sidebar → Ledger and Journal Applet → Error Checking*

Run Error Checking after every CSV import and as part of month-end before generating financial reports.

| Tab | What it lists |
| :--- | :--- |
| **Journal Not Balance** | Journals where total line debits ≠ total line credits. Fix by editing the lines (if still allowed) or voiding and re-posting. |
| **Missing Journal** | Gaps in the `posting_running_no` sequence — indicates a journal was hard-deleted out of band. |
| **Missing Journal Forex Gain Loss** | Forex documents that have not been revalued. Run the Forex Gain/Loss flow. |
| **Update Journal Remarks** | Bulk-edit journal descriptions. |
| **Missing Credit Card Charge** | Credit card transactions awaiting the matching merchant charge journal. |

Click any row to navigate to the offending journal.

## What the system enforces

| Rule | Where enforced | Error on failure |
| :--- | :--- | :--- |
| Company, Ledger, GL Code, Sub-Ledger NOT NULL | DB constraints + DCO validators | NOT NULL violation |
| GL Code and Sub-Ledger must exist (FK) | `JournalDataConsistencyObject` | FK lookup failure |
| Ledger defaults to the PRM ledger if not supplied | `JournalService.createJournal` | `PRIMARY_LEDGER_NOT_EXIST` if no PRM ledger |
| Fiscal period must not be `LOCK_TXN` or `LOCK_ALL` | `FiscalYearService.checkLockFiscalPeriod` | `FISCAL_PERIOD_LOCKED` |
| Total debit + total credit cannot both be zero | `JournalPostingService` | `NO_JOURNAL_CREATED` |
| A posted journal can be voided only once | `JournalPostingService.createJournalGenDocReversePosting` | `GEN_DOC_HAS_BEEN_REVERSED` |
| Forex-flagged documents cannot use Void | Same | `GEN_DOC_IS_FOREX` (use Forex Gain/Loss flow) |
| `posting_running_no` is immutable | `JournalService.generateNSetPostingRunningNo` | — (sequence stamps once) |
| CSV `REFERENCE_NUMBER` unique per company | `JournalImportFileHelperUow.validateExistingReferenceNo` | `REFERENCE NO ALREADY EXIST: ...` |
| CSV file-level debit = credit tally | `JournalImportFileHelperUow.validateTallyOfDebitAndCreditAmount` | `THE LINE TOTAL AMOUNT DEBIT AND CREDIT IS NOT TALLY` |

{{< callout type="info" >}}
**Header-level balance is not enforced on save for manual journals.** The Journal Data Consistency Object checks NOT NULL and FK existence but does not compare `SUM(amt_debit)` to `SUM(amt_credit)`. Always confirm the running totals match before clicking Save. Use *Error Checking → Journal Not Balance* to find any that slipped through.
{{< /callout >}}

## Recurring tasks and adjustments

### Month-end accruals

1. Use **Clone** on last month's accrual journal.
2. Update `date_txn` to the new period end and `reference_num_1` to a new sequence.
3. Adjust any amounts that changed; save.
4. Post the reversal in the next period — either Clone again and swap debits/credits, or use Void if the original was a one-off.

### Reclassifications

Post a manual journal: `Dr correct account / Cr wrong account` for the misposted amount. Reference the original journal's `reference_num_1` in the description. Do **not** hand-edit AUTO journals — they are linked to their source operational document.

### Forex revaluation

Forex gain / loss adjustments are posted by the dedicated **Forex Gain/Loss** processor (using the `FOREX_GAIN` and `FOREX_LOSS` Default GL Codes), not by a manual journal. The system rejects duplicate forex postings with `FOREX_GAIN_LOSS_HAS_BEEN_POSTED` and refuses to Void a forex document with `GEN_DOC_IS_FOREX`.

### Opening balances at cutover

Post a single MANUAL journal dated on or before your go-live date that debits each asset / expense and credits each liability / equity for its opening figure. The journal must balance. See the [Chart of Accounts Setup Guide](/guides/accounting-guides/chart-of-accounts-setup/) for the full migration sequence.

## Gotchas and troubleshooting

| Symptom | Cause | Fix |
| :--- | :--- | :--- |
| Save "succeeded" but no journal appears | Both total debit and total credit were zero — rejected with `NO_JOURNAL_CREATED`. | Re-enter the amounts. |
| Trial balance is suddenly off | An unbalanced manual journal was saved. | Open *Error Checking → Journal Not Balance*, navigate to the journal, edit the lines or void and re-post. |
| Save fails with `PRIMARY_LEDGER_NOT_EXIST` | The company has no `PRM` ledger. | Go to *Companies → open company → Ledgers* and create a Primary ledger. |
| Save fails with `FISCAL_PERIOD_LOCKED` | `date_txn` falls in a period with `closing_status` of `LOCK_TXN` or `LOCK_ALL`. | Change `date_txn` to an open period, or have an admin temporarily set the period to `OPEN`. |
| Void fails with `GEN_DOC_HAS_BEEN_REVERSED` | The journal was already voided. | Post a new MANUAL journal with the correct entries instead. |
| Void fails with `GEN_DOC_IS_FOREX` | The journal carries a forex flag. | Use the Forex Gain/Loss flow, not Void. |
| A new Sub-Ledger appeared that you didn't create | A typo'd GL Code on a new company silently spawns a Sub-Ledger under that code. | Pick GL Codes from the dropdown, never type them. Deactivate the stray Sub-Ledger from the Sub Ledger module. |
| AUTO journal looks wrong | The source operational document (Sales Invoice, Purchase Invoice, etc.) is wrong. | Never hand-edit AUTO journals — they break the link to the source. Fix the source document, or post a separate MANUAL adjustment. |
| CSV import fails: `REFERENCE NO ALREADY EXIST` | A `REFERENCE_NUMBER` in the file matches an existing journal for the same company. | Use a unique prefix per batch, e.g. `JV-2026-01-001`. |
| CSV import fails: every row flagged with tally error | File-level `SUM(LINE_AMOUNT_DEBIT)` ≠ `SUM(LINE_AMOUNT_CREDIT)`. | Audit in Excel before upload; the tally is checked across the whole file, not per journal. |
| Sub-Ledger is mapped to the wrong GL Code | Sub-Ledger to GL Code mapping is fixed once transactions exist — only the description is editable. | Create a new Sub-Ledger under the correct GL Code, post a journal that transfers the balance, then deactivate the old Sub-Ledger. |
| Clone posted with last month's amounts | The clone is created in posted state immediately. | Void the clone, then re-clone and edit the date / amounts before they go out of sync — or set up the recurring entry via Settings rather than Clone. |
