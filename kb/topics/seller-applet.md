# Seller Applet

The seller-side workspace of the marketplace module. A tenant login linked to a merchant entity picks that seller in the sidebar and maintains its marketplace items (`bl_mkp_mst_item_hdr`), per-store stock balances (`bl_mkp_entity_branch_stock_balance`), sees the seller orders (`bl_mkp_seller_order_hdr`) allocated to it from the tenant's sales orders, and edits the purchase invoices and payment vouchers used to settle. Large parts of the applet are template-clone leftovers that are not wired to the backend.

## How it connects

- **merchant-applet** — the seller is a merchant entity; login links decide what a user sees here; entity branches are the seller's stores.
- **seller-admin-applet** — the owner-side queue that should call the manual allocation endpoint; no registry row for it (see findings run 20).
- **internal-sales-order-applet** — every seller order derives from a sales-order line via the allocation queue; `seller_order_alloc_queue` flag on the header.
- **pricebook-applet** — `enable_marketplace` schemes under `PRICING_SCHEME_ITEM`; the allocation query resolves the seller through the scheme's owner entity.
- **doc-item-maintenance-applet** — `fi_item_guid` must be set outside this applet for allocation and the Pages tab.
- **internal-purchase-invoice-applet / internal-payment-voucher-applet** — same documents; those applets are where FINAL (PI) and Create (PV) actually work.
- **cashbook-applet / organisation-applet** — settlement methods and company knock-off rows used by the PI/PV tabs.
- **ecomsync** — seller stock balances feed the `MKP_SELLER_STOCK_BALANCE` calculation (broken roll-up).
- **cp-commerce-admin-applet** — `CPCOMMERCE_SALES_ORDER` headers enter the same allocation queue.
