# Fixed asset register

BigLedger's fixed asset register records what a company owns, what it cost, where it sits and how it
loses value. It is a stand-alone set of tables rather than a generic document: there is no document
type, no FINAL, no numbering series and no data-consistency-object signums. Assets arrive by hand,
by CSV import, or by conversion from a finalised Purchase Invoice (Internal) line. Journals are
assembled by the applet in the browser (acquisition, adjustment, disposal, free-form) or by a
backend job processor (monthly depreciation), and posted straight to the journal endpoint.

## How it connects

- **chart-of-accounts** — three GL codes per asset (asset, depreciation expense, accumulated depreciation) and the company's `PRM` primary ledger, which every journal this applet writes is stamped with. The purchase conversion auto-creates a "Fixed Asset Register" GL code and company link when the `FIXED_ASSET_REGISTER` link is missing.
- **ledger-and-journal** — every effect of this applet is a journal, not a document posting. Transaction types to look for: `DEPRECIATION` (auto_flag `AUTO`, description "AUTO CREATED FROM FIXED ASSET DEPRECIATION PROCESSOR"), `TXN` (Other Journal), and the four asset transaction types. `bl_fi_jrnl_hdr.far_hdr_guid` and `far_depr_run_line_guid` are the back-references.
- **doc-item-maintenance** — an item's `item_txn_type = FIXED_ASSET_REGISTER` is what makes a purchase invoice line convertible, and its `property_json.type` / `property_json.category_guid` seed the asset's type and category.
- **document-approval** — does **not** apply here. This applet has no generic document, no status transitions in `bl_fi_generic_doc_*` and no approval engine of any kind; nothing in the document-approval topic transfers.
- **applet-registry** — the settings menu this applet shows is partly the shared shell's and partly its own, which is why two of the visible "settings" screens have no route in this repo.
- **employee-applet** — the person-in-charge drop-down reads entity headers; the CSV import matches them by name.

## Open questions

- Has any tenant ever produced a non-empty depreciation journal? That requires `fi_depr_subledger_guid` and `fi_acc_depr_subledger_guid` to be populated on `bl_fi_fixed_asset_register_hdr`, and no code path writes them. A read-only count of `bl_fi_jrnl_hdr` rows with `txn_type = 'DEPRECIATION'` that have lines would settle it.
- Is the `FIXED_ASSET_REGISTER_ITEM_TYPE` subscriber link present in the master DB at all, and is any tenant's trigger configuration enabled for it? If not, the purchase-invoice conversion only ever runs through the anonymous endpoint.
- Is the anonymous `fa/fixed-asset-registers/purchase/{guid}` endpoint reachable from outside the tenant network? If so it is a write primitive with no authentication.
- Does `depr_rate` mean a monthly fraction anywhere in practice, or have tenants been entering annual percentages into a field labelled "Depreciation Rate (%)"?
