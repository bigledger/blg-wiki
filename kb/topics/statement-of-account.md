# Statement of account

Batch production of customer statements. A **run** (`bl_fi_stmt_account_run_hdr`) names a period, one or more companies, a customer selector, a printable format and an output mode; the server expands it into one **line** (`bl_fi_stmt_account_run_line`) per company-and-customer pair, renders a PDF per line and, for an e-mail run, sends it. **Templates** and **events** sit above the run: an event is a scheduled run, a template pre-fills an event form. Nothing here posts, moves stock, or changes a balance.

## How it connects

- **customer-maintenance / entity-applet** — the customer's category links and `default_sales_agent` are the *only* two selectors a run has, and the entity's e-mail, address contacts and login subjects are the whole recipient list. A category-less customer with no default sales agent can never receive a statement.
- **organisation** — a run is company-scoped, and the intersection is per company, so a customer trading with two companies gets two statement lines.
- **debtor-report-applet** — the same receivable position for internal use. Customer-reported mismatches between the two exist (`gh:bigledger/customer-repo-f18431#948`), which is worth checking before either page claims they agree.
- **internal-sales-invoice-applet** — only `posting_status = FINAL` documents make a customer eligible; a draft invoice keeps the customer out of the run entirely.
- **printable-format** — the run selects a format with txn type `STATEMENT_OF_ACCOUNT`; the `PRINTABLE` applet setting is the default.
