# Purchase Requisition (Internal)

The internal "we need to buy this" document: items, quantities, requesting branch, preferred supplier. Signums 0/0 — FINAL moves no stock and posts nothing; it only creates open-queue rows so a Purchase Order can knock the lines off. Unlike the Stock Requisition, this applet wires the generic-document approval workflow end to end (submission validated by the backend, approver queue, e-mails, auto-FINAL on approval) — but a plain FINAL is never blocked by approval status.

## How it connects

- **internal-purchase-order-applet** — consumes the open queue (needs the PR → PO company row); its Approval Monitor can require a PR link; its approval header copies the PR submitter (#1070).
- **stock-requisition** — same 0/0 shape; its approval screens are written but not enforced, whereas here the backend validates the submission and auto-finalises.
- **generic-document-approval** — shared tables/processors (`bl_fi_generic_doc_approval_*`, primary / sequence / request processors); PR and PO are the only server doc types offered in Approval Settings.
- **knock-off-configuration** — PR → PO, Jobsheet → PR, GRN → PR rows.
- **workflow-design** — process statuses are labels here, not gates.
- **client-side-permissions** — `*_DISPLAY_PRICING` hide-by-default pattern shared with PO, GRN, Purchase Return (#4399).
