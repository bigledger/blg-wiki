# Inventory Item Maintenance (stock-keeping item record)

The stock side of an item: the `bl_inv_mst_item_hdr` row that ledgers, balances, serials, bins and costing are keyed on. Its commercial twin is the doc item (`bl_fi_mst_item_hdr`); creating a Basic Item there creates and links the inventory record. This applet maintains what the doc item does not: inventory categories, multi-UOM lines, per-location min/max, serial-number import and trace, and the stock aging report.

## How it connects

- **doc-item-maintenance** — creates and links the inventory record (async processor); pushes status; shares category groups/categories; scan codes copied once and then drift.
- **stock-balance / stock-availability** — display the min/max levels and balances keyed on this record; the min/max cron reads the same balance rows.
- **stock-take** — scan lookups depend on this record's scan code and multi-UOM barcodes; a divergent scan code is the documented failure.
- **stock-adjustment / stock-transfer / sales & purchase documents** — produce the ledger and sub-line rows that Stock Card and Trace Serial No read.
- **stock-report** — same `StockReportService` family as the stock aging report.
- **warehouse-management / organisation** — locations and companies that tabs and imports resolve by code.
- **data-fix** — scan-code alignment endpoints live on the inventory item controller; a Data Fix applet feature was requested and delivered for it.
- **emp-etl-sync** — the composite client key uniqueness (`client_key/client_source/client_value`) and `EMP_ITEM_PKID` queries in `InventoryItemService` are the ETL's path into this table.
