# Debtor Report Applet (AR outstanding, aging, statements, historical, AR transactions, collection report, contra)

The Debtor Report Applet is the accounts-receivable reporting front end: seven read-only reports over FINAL customer documents (`bl_fi_generic_doc_hdr` with `arap_*` balances) and one write action, a contra between two open customer documents. It is the most actively developed of the three report applets (157 commits, ~50 in 2026) and has the widest settings surface: ten Field Settings keys, applet-wide defaults with tab ordering, a working personal Default Selection, aging periods, and three statement templates.

## How it connects

- **creditor-report-applet** — same code base with `AP_*` types; fewer Field Settings keys, dead personal defaults, two purchase reports instead of the collection report.
- **debtor-and-creditor-report-applet** — both sides in one menu, almost no settings, no contra.
- **internal-receipt-voucher-applet** — settlements shown in Settlement tabs, AR Transaction and Collection reports; contras created here change the balances its settlement picker offers.
- **internal-sales-invoice-applet / credit note / debit note / return / cash bill** — the documents whose `arap_bal` is reported; only FINAL.
- **entity-applet / credit-limit** — AR type decides inclusion; Credit Limit and Credit Term columns come from the entity (2026-05).
- **commission-scheme-applet / sales-report-applet** — collection-based commission and salesman analysis use the same invoice–receipt pairing the Collection report shows.
- **generic-doc-popup** — the shared `akaun-generic-doc-view-dialog` honours `HIDE_DOC_POPUP_COST_AMOUNT` / `HIDE_DOC_POPUP_GP` from any applet's settings; other applets embedding the popup can use the same keys.
- **aging-period / printable-format / historical-ageing / arap-contra** — as for the creditor applet.
