# Commission Scheme applet

A commission scheme is master data that says which sales documents qualify (header, multi-line and single-line rule groups) and how much cash commission or how many membership points each downline level earns (treatment). The applet also maintains Sales Groups and tiered Pricing Models. It never pays: the Sales Commission posting run and the scheduled membership-points run read the ACTIVE schemes.

## How it connects

- **sales-commission** — the Sales Commission Applet's posting is the only consumer that pays cash; PRICING_MODEL treatments only produce numbers in its full-commission cycle pass.
- **membership-points** — the scheduled points run reads Level 0 membership_points; company settings on Organisation decide which documents are scanned.
- **mlm-lineage** — `MLM` schemes walk `bl_mlm_lineage_hdr` from the buying member; level n treatment goes to the level n upline.
- **sales-agent** — `sales_entity_hdr_guid` on the invoice/order is the paid agent for SALES_AGENT schemes and the subject of the Employee Category rule.
- **employee-category** — labels in the `EMPLOYEE_CATEGORIES` list (Employee Applet › Category tab) are the only working way to target a group of agents, since SALES_GROUP is unimplemented.
- **item-category** — item categories from Inventory Item Maintenance feed Item Category and category-regex rules.
- **pricing-scheme** — `bl_fi_mst_pricing_scheme_hdr/link` supplies the Pricing Scheme price source (item sales_unit_price × qty); no wiki page covers pricing schemes.
- **cp-commerce-website** — website ↔ scheme link table; the CP Commerce Admin page documents the tab.
