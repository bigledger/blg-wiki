# SST filing (MY-SST)

How a Malaysian SST-registered company turns already-taxed documents into an SST-02 return. Three layers: a **tax year** (`bl_fi_filing_year_hdr`) fixes the filing frequency; a **filing cycle** (`bl_fi_filing_hdr`) is one taxable period; **filing** copies the taxed lines of eligible generic documents into a frozen snapshot table (`bl_fi_tax_txn`), and the SST-02 is computed entirely from that snapshot. No journal, no stock, no generic document of its own.

## How it connects

- **tax-configuration** — MY-SST's Tax Code screens write the same `bl_fi_cfg_tax_code` table as the Tax Configuration applet, with a different `tax_country` encoding (`MYS` vs "Malaysia"), no rate rounding, and the tariff code in the `tax_tariff_code` column rather than `property_json`. A row created in one cannot be edited in the other. The SST-02's hard-coded code literals make the *naming* of those rows load-bearing in a way Tax Configuration never signals.
- **organisation** — Part A of the SST-02 reads `bl_fi_mst_comp.sst_registration_id`; the tax year inherits its period bounds from the company's fiscal year.
- **doc-item-maintenance** — the tax code on the item is what puts `tax_gst_type`, `tax_gst_code`, `tax_gst_rate` and `tax_tariff_code` on a document line; those four columns are the only thing SST filing ever reads from a document line.
- **internal-sales-invoice-applet / internal-purchase-invoice-applet** — the documents that get filed. The service-tax payment basis means a sales invoice's *settlement* date, not its own date, decides its SST period.
- **chart-of-accounts / financial-report-applet** — the tax GL balance comes from the documents' journals (company default `OUTPUT_TAX` / `INPUT_TAX` links). Filing writes nothing to the ledger, so a reconciliation between the SST-02 and the tax GL accounts compares two independently-derived numbers.
- **e-invoice** — a separate LHDN obligation over the same documents; the LHDN tax classification comes from `einvoice_taxable_type_code`, not from `tax_gst_type`, so an e-Invoice that validates says nothing about whether the SST-02 will be right.
- **document-approval** — SST filing has no approval engine of any kind. Lock is the only state change, and it checks no permission.
