# Supplier Maintenance (supplier master)

The supplier record every purchase requisition, order, goods receipt, purchase invoice, note, payment voucher and self-billed e-Invoice reads: identity, bank and tax details, AR/AP type, credit term and limit, item pricing, category, branch and company links, and the login link that supplier-portal applets depend on.

## How it connects

- **customer-maintenance** — same table (`bl_fi_mst_entity_hdr`), same merge machinery, same credit-term/limit shape. One entity may be both; the flag is a tick-box on the record, set by the tenant. Differences worth keeping straight: supplier credit-limit `amount` is integer-only here while the customer applet allows 2 dp, and nickname uniqueness is enforced for suppliers only.
- **entity** — Entity Maintenance creates rows with any combination of type flags and maintains the same category trees.
- **chart-of-accounts** — the supplier's AR/AP type is what selects the payable account on a purchase posting (`AP_TRADE` → `CREDITOR`, `AP_OTHER` → `CREDITOR_NON_TRADE`, `AP_EMPLOYEE` → `EMPLOYEE_OTHER_PAYABLE`).
- **organisation** — companies and branches for the linking tabs; the company e-Invoice/Peppol enablement and Knock Off Configuration that decide what this master data can be used for.
- **stock-replenishment** — reads the Item Pricing (Entity Pricing) rows; links whose entity is inactive or not of type supplier are filtered out.
- **e-invoice / peppol** — `EINVOICE_SELF_BILLED` routes the supplier into the self-billed pipeline (types 11–14) with the supplier as issuer; the default Peppol participant ID is the routing receiver. The TIN auto-lookup button (ID type + ID value present, TIN blank) is shared across the four master applets.
- **entity-merge** — the merge is a platform backend function shared with customer maintenance, not per-applet; document it once and link both.
- **supplier-delivery-order-applet** and the `*-supplier-access-*` family — all gated on the Login tab link.
